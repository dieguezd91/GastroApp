# GastroApp UI/UX Interactive Prototype

- Target directory: `prototypes/ui-ux/` (standalone, zero changes to main Blazor app or `data.json`)
- Reference branch inspected: `feat/stock-movements`
- Standards: WCAG 2.2 AA + Google Chrome Modern Web Guidance (`dialog`, `prevent-page-scroll-under-modal-dialog`, `light-dismiss-a-dialog`, `persistent-toast-notifications`, `responsive-table`, `forms`, `validate-input-after-interaction`, `accessible-error-announcement`, `accessibility`, `form-factor-adaptation`, `responsive-design`, `navigation-drawer`, `tabs`, `color`, `css`)

## Specs

- **S1 — Scope & isolation**: Design and build an interactive web prototype in `prototypes/ui-ux/` without implementing production backend logic, migrations, or modifying any files of the main application. Clearly distinguish implemented features, proposals, and assumptions.
- **S2 — Roles & navigation**: Differentiated UX for the two existing roles only (`Administrador` and `Empleado`), sharing visual identity while adapting navigation, information, and actions to role permissions, plus a demo-only role switcher and login flow.
- **S3 — Design system & UX direction**: Contemporary hospitality SaaS visual identity (typography, colors, spacing, custom SVG iconography without emojis, interactive states, Argentine Spanish, ARS currency, local date/number formats), WCAG 2.2 AA accessibility, responsive desktop (1440px), touch tablet (1024px), and mobile (390px), plus empty/error/validation/loading/success states.
- **S4 — Priority 1 (POS flow)**: Employee/Admin full flow: catalog, categories (`Todos`, category, `Sin categoría`), search, cart, quantities, line observations, per-line & general discounts (`None`/`Percentage`/`Fixed`), checkout with all 6 payment methods (`Efectivo`, `Tarjeta de débito`, `Tarjeta de crédito`, `Transferencia`, `Mercado Pago`, `Otro`) and mixed payments, cash received + live change (`Vuelto`), confirmation receipt, and real domain errors (insufficient recipe ingredient stock, closed register).
- **S5 — Priority 2 (Cash register flow)**: Admin full flow: contextual dashboard activity, open register, KPI strip, manual cash movements (`Ingreso`, `Gasto`, `Retiro`), denomination-based cash count (`Arqueo y cierre de caja`) with live difference (`Exacto`/`Sobrante`/`Faltante`), stale-movement detection/refresh, payment method breakdown with completeness status, close confirmation, and read-only cash register history.
- **S6 — Priority 3 (Catalog, costing & inventory flow)**: Admin full flow: review products & categories (active toggle, margin thresholds `<0` / `<30%` / `>=30%`), recipes & costing (yield, latest invoice cost, cost variation `<10%` / `10-30%` / `>=30%`, recalculate), ingredients & stock alerts (7-day coverage, `Agotado`/`Bajo mínimo`), actionable adjustments, waste registration (`WasteCategory`), movement ledger, 3-step physical stock count, plus suppliers & purchase invoices.
- **S7 — Secondary & Proposal screens**: Implemented screens (`Historial de ventas` with detail, timeline, void/cancel, partial/full refunds with `Vuelve a stock`/`Merma`; `Resumen del día`) and clearly badged Proposal screens (`Reportes y rentabilidad` M20, `Configuración del negocio` M01/M18/M21).
- **S8 — Browser validation & screenshots**: Validate in browser across Desktop (1440px), Tablet (1024px), and Mobile (390px) for keyboard navigation, focus states, touch target sizes, form validation/error states, zero overflow/overlap, and capture screenshots of primary screens in `prototypes/ui-ux/screenshots/`.
- **S9 — Deliverables**: Executable prototype, reusable design system doc, role-based navigation map, UX decisions log, screenshots, and local run instructions.
